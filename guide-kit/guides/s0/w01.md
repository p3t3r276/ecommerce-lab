## Buổi 001 · T3 03/11 · Cài công cụ
**Loại:** manual

### Mục tiêu
Máy có .NET 10 SDK, Docker, Node, k6, Aspire CLI, dotnet-ef và template Aspire; mọi lệnh in ra version.

### Vì sao
- Aspire AppHost chạy container qua Docker, nên Docker Desktop phải đang chạy trước mọi thứ khác.
- Khác Detail Plan: thêm `dotnet new install Aspire.ProjectTemplates`, vì buổi 003 cần template `aspire-apphost` mà Detail Plan quên cài (C-s0-02, I-16). `nx` không cài global, luôn dùng `npx nx`.

### File
Không có (reference dùng commit rỗng `b001`).

### Các bước
1. Cài .NET 10 SDK, Docker Desktop, Node, k6 (macOS: `brew install k6`).
2. Mở Docker Desktop và đợi daemon sẵn sàng.
3. Cài tool và template:
   ```bash
   dotnet tool install -g Aspire.Cli
   dotnet tool install -g dotnet-ef
   dotnet new install Aspire.ProjectTemplates
   ```
4. Tạo thư mục repo và chạy `git init -b master` (nhánh mặc định là `master`, D-010).

### Kiểm chứng
```bash
dotnet --info
aspire --version
dotnet ef --version
dotnet new list aspire
docker ps
node -v
k6 version
```
Kết quả đã chạy trong reference (mức `run`): SDK 10.0.303, Aspire CLI 13.6.4, dotnet-ef 10.0.14, template `aspire-apphost` và `aspire-servicedefaults` 13.6.4, k6 v2.3.0, Docker 29.x. Node trong reference là v26.0.0, không phải 22.x như thiết kế yêu cầu; chưa kiểm chứng Nx 21.5/Angular 20 với Node này (sẽ biết ở tuần 4). Nếu bạn cài được Node 22 LTS thì nên dùng.

### Thử đổi số
| Thay đổi | Cách làm | Quan sát | Nhãn |
|---|---|---|---|
| Yêu cầu một SDK không có | Tạo `global.json` với `"version": "10.0.999"` và `"rollForward": "disable"`, chạy `dotnet build` | Lỗi "A compatible .NET SDK was not found. Requested SDK version: 10.0.999". Với `latestFeature` của kế hoạch, 10.0.999 vẫn lỗi vì không có bản 10.0.x nào >= 999; `disable` làm thông báo không phụ thuộc band đã cài. Xóa file thử này sau khi xem. | đã chạy thử |

### Lỗi thường gặp
- **`docker info`: "failed to connect to the docker API ... docker.sock"**: Docker Desktop chưa chạy → mở Docker Desktop, poll `docker ps` tới khi daemon lên.
- **`timeout: command not found` trên macOS**: macOS không có `timeout` → dùng `aspire run --detach` rồi `aspire stop` (các buổi sau).

## Buổi 004 · CN 08/11 · Postgres + pgAdmin, 8 database
**Loại:** scaffold

### Mục tiêu
AppHost chạy Postgres (volume `shoplab-pg`) cùng pgAdmin, với 8 database khai báo bằng `AddDatabase`; Postgres xanh trên dashboard.

### Vì sao
- Mỗi service một database (pattern database-per-service); khai báo bằng `AddDatabase` thay vì `init.sql`, nên mọi người có cùng 8 database ngay khi `aspire run`. `AddDatabase` tạo database lúc Postgres khởi động kể cả khi chưa service nào tham chiếu.
- Volume tên cố định `shoplab-pg` giữ dữ liệu qua các lần chạy lại. Nếu bỏ `WithDataVolume`, dữ liệu nằm trong volume ẩn danh.
- Không ghim image tag (D-011): Postgres 18 xuyên suốt, dùng image mặc định của Aspire (`postgres:18.3` ở Aspire 13.6.4). Reference ban đầu ở `b004` ghim `17`, sau đó sửa bằng commit `b004-fix` (nằm sau tag `w01`); **guide theo bản đã sửa**. Image 18 đổi cấu trúc thư mục data, nên volume tạo bởi bản 17 không dùng lại được: xóa bằng `docker volume rm shoplab-pg`. Tag mặc định đổi theo từng bản Aspire, vì vậy nếu bản Aspire của bạn không cho 18.x thì thêm `.WithImageTag("18")`.

### File
- `src/AppHost/AppHost.cs`, `src/AppHost/AppHost.csproj`, `Directory.Packages.props`

### Code
```bash
dotnet add src/AppHost package Aspire.Hosting.PostgreSQL
```
Với CPM, `dotnet add` ghi version thẳng vào `Directory.Packages.props` (13.6.4) và csproj chỉ có `PackageReference` không version.

```xml
<!-- Directory.Packages.props -->
    <!-- AppHost -->
    <PackageVersion Include="Aspire.Hosting.PostgreSQL" Version="13.6.4" />
```

```xml
<!-- src/AppHost/AppHost.csproj -->
  <ItemGroup>
    <PackageReference Include="Aspire.Hosting.PostgreSQL" />
  </ItemGroup>
```

```csharp
// src/AppHost/AppHost.cs
var builder = DistributedApplication.CreateBuilder(args);

var pg = builder.AddPostgres("pg")
    .WithDataVolume("shoplab-pg")
    .WithPgAdmin();

// One database per service, all declared up front (no init.sql).
pg.AddDatabase("catalogdb");
pg.AddDatabase("customerdb");
pg.AddDatabase("inventorydb");
pg.AddDatabase("orderingdb");
pg.AddDatabase("paymentdb");
pg.AddDatabase("discountdb");
pg.AddDatabase("flashsaledb");
pg.AddDatabase("storedb");

builder.Build().Run();
```

### Kiểm chứng
```bash
dotnet build shoplab.slnx
aspire run --detach
aspire describe
docker exec <tên container pg> sh -c 'PGPASSWORD="$POSTGRES_PASSWORD" psql -h localhost -U postgres -tAc "select datname from pg_database"'
aspire stop
```
Kết quả đã chạy với bản `b004-fix` (mức `run`): container `postgres:18.3` và `dpage/pgadmin4:9.15.0` lên; `aspire describe` báo `pg`, `pgadmin` và các database Healthy; truy vấn trả `postgres`, `template0`, `template1` và 8 database của service; `show server_version` cho `18.3`. Dashboard chưa được mở bằng trình duyệt; bạn nên mở để thấy Postgres xanh, rồi vào pgAdmin (cổng ngẫu nhiên, xem dashboard, đã cấu hình sẵn server) để thấy 8 database. Mật khẩu Postgres do Aspire sinh, chỉ có trong biến môi trường container (hoặc user secrets của AppHost), nên `psql` phải có `PGPASSWORD`. Sau `aspire stop`, container pgAdmin cũ có thể còn vài giây rồi mới biến mất.

### Thử đổi số
| Thay đổi | Cách làm | Quan sát | Nhãn |
|---|---|---|---|
| Bỏ volume đặt tên | Xóa `.WithDataVolume("shoplab-pg")`, tạo một bảng trong pgAdmin, restart `aspire run` | Dự kiến bảng biến mất vì data nằm trong volume ẩn danh. Đặt dòng lại sau khi thử. | dự đoán |
| Đổi major version với volume cũ | Chạy một lần với tag khác (ví dụ 17) rồi đổi sang 18 mà không xóa volume | Postgres 18 không đọc được data dir của 17, phải `docker volume rm shoplab-pg` (builder gặp việc này khi chuyển 18 → 17 → 18, không chủ ý) | đã chạy thử |

### Lỗi thường gặp
- **Mọi resource Unhealthy một lúc sau `aspire run`**: container còn đang khởi động → đợi và poll lại.
- **`psql`: `fe_sendauth: no password supplied`**: mật khẩu do Aspire sinh → đọc bằng `docker exec <pg> printenv POSTGRES_PASSWORD` hoặc dùng `PGPASSWORD="$POSTGRES_PASSWORD"` trong `sh -c` như trên.
- **Postgres không lên sau khi đổi major version**: volume `shoplab-pg` còn dữ liệu của bản cũ → `docker volume rm shoplab-pg`.
